# 추출·정규화 계약 (Extraction Contract)

> 작성 2026-09-06 · 아직 문서를 취득하지 않았다. 규칙을 먼저 정한다.

## 0. 왜 계약이 필요한가

정답 라벨과 chunk 좌표는 **추출된 텍스트의 문자 위치**를 가리킨다.
추출기나 정규화 규칙이 조금만 달라져도 좌표가 통째로 밀린다.

**HWPX가 XML 기반이라는 사실만으로 좌표가 안정적이라고 말하지 않는다.**
같은 파일이라도 표를 어떤 순서로 펼치는지, 셀 경계를 어떤 문자로 잇는지,
빈 문단을 남기는지에 따라 결과 텍스트가 달라진다. 안정성은 형식이 주는 것이 아니라
**아래 계약을 고정해야 생긴다.**

## 1. 재현의 정의

다음 네 값이 **모두 같을 때만** "같은 추출 결과"라고 부른다.

| 값 | 뜻 |
|---|---|
| `document_sha256` | 원본 파일의 해시 |
| `extracted_text_sha256` | 정규화까지 끝난 텍스트의 해시 |
| `extractor_version` | 추출 구현의 버전 |
| `normalization_version` | 정규화 규칙의 버전 |

넷 중 하나라도 다르면 **좌표를 재사용하지 않는다.** `corpus_version`을 올리고 라벨을 다시 맞춘다.

이 값들은 `config.yaml`과 모든 결과표에 함께 적는다.

## 2. 정규화 규칙 `norm-v1`

추출 직후 다음 순서로 적용한다. **순서를 바꾸면 결과가 달라지므로 순서도 계약의 일부다.**

1. **유니코드 정규화** — `unicodedata.normalize("NFC", text)`
   한글 자모 분리형(NFD)으로 저장된 파일이 있어 먼저 통일한다
2. **줄바꿈 통일** — `\r\n` · `\r` → `\n`
3. **제어문자 제거** — `\t`를 제외한 C0 제어문자(`\x00`–`\x08`, `\x0b`, `\x0c`, `\x0e`–`\x1f`) 삭제
4. **공백 문자 통일** — non-breaking space(` `), 전각 공백(`　`),
   zero-width(`​`, `﻿`)를 일반 공백으로 바꾸거나 삭제
5. **행 내부 공백 축약** — 연속 공백/탭을 공백 1개로. **줄바꿈은 축약하지 않는다**
6. **행 끝 공백 제거**
7. **빈 줄 축약** — 연속된 빈 줄을 최대 1개로
8. **문서 끝 개행 정리** — 파일 끝은 `\n` 하나로 끝낸다

### 2.1 문단

- 원본의 문단 하나 = 출력의 줄 하나. 문단 안에서 임의 줄바꿈을 넣지 않는다
- 문단 사이는 빈 줄 하나로 구분한다
- 목록(`○`, `-`, `1.` 등) 기호는 **지우지 않는다.** 원문 문자열을 그대로 둔다

### 2.2 표 — 가장 결정이 많이 필요한 부분

RFP의 예산·배점·일정이 표에 있어서, 표를 어떻게 펼치느냐가 검색 결과를 좌우한다.

- 표는 **행 단위로 한 줄씩** 펼친다
- 같은 행의 셀은 구분자 **` | `**(공백-파이프-공백)로 잇는다
- 병합 셀은 **값을 반복하지 않고** 첫 위치에만 두고, 나머지 자리는 빈 문자열로 남긴다
- 표 시작 앞과 끝 뒤에 빈 줄 하나씩 넣는다
- 표 안의 줄바꿈은 공백으로 바꾼다 (행이 쪼개지지 않게)
- 표에 캡션이 있으면 표 **앞** 줄에 그대로 둔다
- **표 전용 마크업(마크다운 파이프 표 등)으로 변환하지 않는다.** 원문에 없던 문자를 넣으면
  좌표가 원문과 어긋난다

### 2.3 머리말·꼬리말·쪽번호

- 매 쪽 반복되는 머리말·꼬리말과 쪽번호는 **제거한다**
- **구현은 반복 횟수 임계가 아니라 구조로 제거한다.** HWPX는 머리말·꼬리말·쪽번호를
  `<hp:header>` · `<hp:footer>` · `<hp:pageNum>` 같은 별도 요소로 표시하므로,
  그 서브트리를 통째로 건너뛴다. 휴리스틱보다 오탐이 없다
  (`extraction/hwpx.py`의 `_SKIP`)

> **`page` 는 아직 채우지 못한다.** HWPX 본문 XML(`Contents/section*.xml`)에는
> 쪽 경계가 들어 있지 않다. 쪽 나눔은 열어서 배치할 때 정해지기 때문이다.
> 그래서 chunk 메타의 `page`는 **`null`(unknown)** 로 두고, 판정은 `char_*` 좌표로만 한다.
> 쪽 정보가 필요해지면 별도 수단을 찾고 `normalization_version`을 올린다.

### 2.4 각주·이미지·수식

- 각주 본문은 **그 각주가 달린 문단 바로 뒤에** 붙인다.
  원래 "해당 쪽 뒤"로 적었으나 §2.3처럼 쪽 경계를 알 수 없어 문단 기준으로 바꿨다
- 이미지는 대체 텍스트가 있으면 그대로, 없으면 **아무 것도 넣지 않는다**
  (`[이미지]` 같은 자리표시자를 넣으면 원문에 없던 문자가 생긴다)
- 수식은 추출되는 문자열 그대로 둔다

## 3. 좌표 기록

정규화가 끝난 텍스트를 기준으로 다음을 기록한다.

```json
{
  "document_id": "doc-001",
  "extracted_text_sha256": "…",
  "page": 12,
  "section": "3.2 예산",
  "char_start": 8412,
  "char_end": 8907
}
```

- `char_*`는 **파이썬 문자열 인덱스**(코드포인트 기준)다. 바이트 오프셋이 아니다
- `page`·`section`은 사람이 확인할 때 쓰는 보조 정보이고, 판정은 `char_*`로만 한다

## 4. 육안 대조 체크리스트

추출을 한 번 돌린 뒤, **원본을 열어 놓고** 아래를 직접 확인한다.
하나라도 어긋나면 `normalization_version`을 올리고 다시 돌린다.

**표본 선정** — 표가 있는 쪽 2곳, 본문만 있는 쪽 1곳, 목록이 있는 쪽 1곳.

- [ ] 첫 쪽과 마지막 쪽의 첫 문장·마지막 문장이 원본과 같은가
- [ ] 예산·금액이 들어간 표의 **행 수와 열 수**가 원본과 같은가
- [ ] 금액 숫자에 쉼표·단위가 원본 그대로 남아 있는가 (`1,199,886,020원`)
- [ ] 병합 셀이 있는 표에서 값이 **중복 반복되지 않았는가**
- [ ] 배점표의 항목-배점 짝이 어긋나지 않았는가
- [ ] 목록 기호(`○`, `-`, `가.`)가 사라지지 않았는가
- [ ] 쪽번호·머리말이 본문 중간에 섞여 들어오지 않았는가
- [ ] 같은 문장이 두 번 나오지 않는가 (머리말 제거 실패 징후)
- [ ] 한글이 자모 분리(`ㄱㅏ`)로 깨진 곳이 없는가
- [ ] 임의로 삽입된 문자(`[이미지]`, `|---|` 등)가 없는가
- [ ] 문서 전체 문자 수를 기록했는가 — 재추출 시 첫 번째 비교값

확인 결과를 `evidence/<experiment_id>/README.md`에 표본 쪽 번호와 함께 남긴다.

## 5. 구현

`extraction/` 패키지에 있다. 서비스 런타임(`app/`)과 분리돼 있고 표준 라이브러리만 쓴다.

| 파일 | 역할 |
|---|---|
| `extraction/hwpx.py` | ZIP·XML 안전 읽기와 본문 조립 |
| `extraction/normalize.py` | `norm-v1` 8단계 |
| `extraction/version.py` | `extractor_version` · `normalization_version` |
| `tools/extract_doc.py` | 파일 하나를 검사·추출하고 **해시만** 출력하는 CLI |

버전은 `extractor_version = hwpx-owpml-v1` · `normalization_version = norm-v1`.

### 5.1 신뢰할 수 없는 파일 전제

| 위협 | 대응 |
|---|---|
| 경로 순회 (`../`, 절대 경로, `C:\`) | 항목 이름을 전수 검사하고 하나라도 걸리면 파싱 전에 중단 |
| ZIP 폭탄 | 항목 수 5,000 · 항목당 50MB · 전체 200MB · 압축률 200배 상한 |
| 암호화 항목 | ZIP 플래그 비트로 확인하고 있으면 중단 |
| XXE·엔티티 확장 | XML 바이트에 `<!DOCTYPE`·`<!ENTITY`가 있으면 **파싱하지 않는다** |
| 첨부 바이너리·OLE·스크립트 | `BinData/` · `Preview/` 등은 **열지 않는다.** `mimetype`과 `Contents/section*.xml`만 읽는다 |
| 임시 디렉터리 유출 | 전체 압축을 풀지 않고 필요한 항목만 스트림으로 읽는다 |

섹션 순서는 파일명 번호로 정렬한다 — 사전순이면 `section10`이 `section1`보다 먼저 온다.

구조가 예상과 다르면 **조용히 빈 결과를 내지 않고 예외를 던진다**
(`mimetype` 불일치, 섹션 없음, 본문 블록 0개).

## 6. 아직 정하지 않은 것

- **실제 문서로 검증하지 않았다.** 아래 §4 육안 대조는 원본을 받은 뒤에 한다.
  지금까지의 검증은 합성 fixture 기준이다
- 표 안의 표(중첩 표) 처리 — 실제로 나오면 그때 규칙을 추가하고 버전을 올린다
- 쪽(`page`) 정보 확보 수단
